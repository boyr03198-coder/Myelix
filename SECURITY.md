# Security Policy

## Supported Versions

During early development, only the latest development branch is supported.

| Version | Supported |
|---------|-----------|
| Current Development | Yes |

---

## Reporting a Vulnerability

If you discover a security issue in Myelix:

- Do **not** create a public issue.
- Report the vulnerability privately to the project maintainer.
- Include:
  - Description
  - Steps to reproduce
  - Impact assessment
  - Suggested mitigation (if known)

The project aims to acknowledge reports promptly and address confirmed issues as quickly as practical.

---

## Security Principles

Myelix is designed with a security-first architecture.

Core principles include:

- Least privilege
- Secure by default
- Defense in depth
- Signed updates
- Signed plugins
- Secure local storage
- No embedded private keys
- Permission-based automation
- Audit logging for privileged operations

---

## Scope

Security considerations apply to:

- Desktop client
- AI integrations
- Plugin system
- Update system
- Authentication
- Licensing
